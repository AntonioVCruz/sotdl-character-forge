Como ler estes wireframes

  1. iCada tela = frame cinza + coluna amarela de notas. Números azuis no frame ↔ notas.
  2. iO componente ChoiceSlot (1b) é desenhado uma vez e reutilizado em todos os passos.
  3. iConteúdo 100% fictício. Termos oficiais do jogo em inglês; UI em pt-BR.

Acessibilidade (vale para tudo)

  1. • Navegação completa por teclado; ordem de Tab = ordem visual.
  2. • Foco visível (contorno azul 3px) em todo controle.
  3. • Todo controle tem rótulo; ícones sempre com texto.
  4. • Esc fecha modais/drawers e devolve o foco a quem abriu.
  5. • Badges de estratégia/estado são texto, não só cor.
  6. • Rolagens anunciadas via região aria-live ("3d6: 4, 5, 3 = 12"); Histórico é uma lista legível por leitor de tela.

Interações

  1. 1Título = slot · contexto (Ancestry, fonte, página, dado).
  2. 2Badge de estratégia sempre visível em texto. Muda para "manual" se o usuário escolher na lista.
  3. 3"Rolar novamente" só existe depois de um resultado. "Travar" protege o slot de Sortear/Gerar tudo. Ações indisponíveis ficam visíveis, tracejadas, com motivo.
  4. 4Resultado sorteado é PRÉVIA: não altera a ficha até "Confirmar". "Descartar" volta ao valor anterior.
  5. 5Consequências: "Aplicadas" ou "Requerem revisão" (link leva ao passo afetado).
  6. 6Rastro expansível: expressão, cada face, total, faixa, tabela, fonte/página, seed, índice de rerolagem.
  7. 7Lista manual mostra TODAS as opções; inválidas desativadas com o motivo. Nunca escondidas.
  8. 8"Ver dados e fonte" abre painel inline com id, versão, curadoria.
